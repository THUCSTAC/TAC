# 2025 春 · 作业评分与查重

课件 by 陈晟祺（与 2024 秋第九讲同源，更新为当学期版本），核心内容参见 [2024 秋 作业评分与代码查重](../2024A/grading.md) 的完整记录。要点：

- 选做与必做：无论黑盒还是白盒，在规模较大时都可设置选做项目（分数）。例如黑盒 80%（基础要求 60% + 提高要求 20%），提供合计约 50% 的可选分；白盒选做可作为加分（如代码风格明显优秀）。
- 必做项目着重考察课程基础内容；详细描述要求、控制难度，给学生成就感；注意内容的递进和依赖关系，防止学生 "卡住"。
- 选做项目作为提高要求，可适当发挥；提供多个不同方向，按难度给分；可留出开放内容，给感兴趣的同学探索空间（谨慎提供分数奖励）。
- 必须严格控制总分，不要留下内卷空间！
- 评分标准：必须预先确定并使用统一标准；每个赋分要求应详尽规定；不推荐主动抹平区分度；是否公布详细标准需权衡——过于含糊学生难以预期，过于详细易过拟合、学生和助教都失去自主空间。
- 评分反馈应及时且详细；推荐做法是列举所有可能的评分点，批阅时详细标注，再根据规则计算分数并生成对应评语；善用公式/脚本自动化生成重复部分、内置检查规则。
- 迟交处理：以基于迟交时间衰减赋分的折中方案平衡 "宽松→拖延" 与 "严苛→冒险抄袭"；无论何种方案都应在课程开始时（任何作业开始前）确定并明确告知。
- 组队作业：不同组队方式的利弊；组员数量不同可采用比例折扣；组内工作量不均可通过验收逐个提问、全过程评价与及时干预缓解（CATME、SIGCSE 2023/2022 的组队评价论文）。
- 查重：不是为了不相信同学，而是维护学术诚信；典型往年代码/讲解录像/Copilot 案例；工具 Stanford MOSS、JPlag、JiePlag（@jiegec 重写）；分析流程与约谈、判断的核心准则。
- 编程作业分数划分：黑盒（客观、可自动化、70%-90%）与白盒（主观、人工评判、10%-30%）；黑盒中是否公开测试用需权衡，推荐公开部分 + 隐藏测试；可设性能分但防内卷；自动化评分方案由简到繁；白盒也应明确评分项目与标准避免助教间偏离过大。
